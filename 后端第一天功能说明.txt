进入某个商品的“图片方案”标签后：

- 没有方案：显示“还没有图片方案”和“新建主图方案”按钮。
- 已有方案：显示方案名称、草稿／已确认状态，点击可以打开。
- 点击新建：进入方案编辑区域。

编辑区域先放这几个字段：

| 字段         | 怎么操作                       | 示例                           |
| ------------ | ------------------------------ | ------------------------------ |
| 方案名称     | 用户填写，默认“主图方案 1”     | 车灯白底主图                   |
| 图片用途     | 本轮固定为“商品主图”           | 主图                           |
| 使用的参考图 | 从当前商品已经上传的图片中勾选 | 勾选整体图和接口细节图         |
| 制图要求     | 用户写希望得到什么图片         | 简洁背景，完整展示商品         |
| 生图提示词   | 多行文本，可编辑               | 一段详细的构图、外观与参考要求 |

“制图要求”是你的简短意图；“生图提示词”是以后交给生图模型的具体指令。本轮可以手工填写测试，下一轮由文本模型根据要求生成提示词。

**按钮的行为要明确：**

| 操作           | 点击后必须发生什么                                       |
| -------------- | -------------------------------------------------------- |
| 保存草稿       | 调用后端保存当前内容；成功后提示“已保存”，失败时保留输入 |
| 取消修改       | 恢复上一次成功保存的内容；新建但未保存的方案则退出       |
| 确认方案       | 将已保存的草稿标记为“已确认”；有未保存修改时，先提示保存 |
| 打开已确认方案 | 可以查看其内容；原内容保持不变，后续修改通过新草稿进行   |

**“确认方案”在这一轮只表示：你认可这份制图要求。它不会调用生图 API，也不会产生图片。**

后端本轮负责四件事：

1. 读取当前商品的方案列表和详情。
2. 创建方案，并关联正确的商品。
3. 更新草稿，保存选中的参考图 ID 和文本内容。
4. 确认方案，保存确认状态。

参考图必须属于当前商品。方案记录需要有自己的稳定 ID；商品移动文件夹后，方案仍跟随商品。已有实体和路由能复用的，就沿用现有实现。

**完成标准直接用一个例子验收：**

1. 打开你的 H4 商品，新建“车灯白底主图”。
2. 选择两张参考图，填写制图要求和提示词，保存。
3. 刷新页面，再重启后端，重新打开后内容完整。
4. 修改提示词，再次保存，重新打开能看到修改。
5. 确认方案，显示“已确认”；确认内容能够再次读取。
6. 保存失败时，页面保留输入，不显示保存成功。

这一轮交付时，小何需要给你看：**页面操作结果、实际保存接口、数据库里的对应记录。**

接下来第二轮才做一件新事：增加“AI 生成提示词”按钮，将**商品事实＋所选参考图信息＋制图要求＋Skill 规则**发送给文本模型，把返回结果填入提示词区域，仍然由你编辑、保存、确认。
