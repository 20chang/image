# 通用流程

所有图片族共用的处理顺序。本文件不写死任何商品资料；商品事实每次调用作为输入传入。

## 1. 读取商品事实

- 来源：`ProductOut.name` / `market` / `facts`
- 以用户填写的事实为准；不足之处列入「待确认问题」，不自行编造
- `market`（目标市场）影响合规与文案语言，需一并读入

## 2. 理解参考图及使用范围

每张选用的参考图有：

| 字段 | 含义 |
|------|------|
| `refImageId` | 图片身份，保留原 ID |
| `productRelation` | 同款同规格 / 其他商品 / 不含商品 / 不确定 |
| `aiStatus` | 经过 AI 处理 / 未经 AI 处理 / 不确定 |
| `desc` | 该图自身备注 |
| `roles[]` | 本次方案中的角色（可多个） |
| `useFor` | 本次参考什么 |
| `ignore` | 本次忽略什么 |

**角色**（来自 `referenceUsage[].roles`）：

| 角色 | 含义 | 约束 |
|------|------|------|
| `primary` 主体依据 | 决定商品整体外观 | 至多一张；应为同款同规格 |
| `detail` 细节补充 | 接口、支架、线束等指定部位 | 优先同款 |
| `usage` 安装与使用 | 安装位置、朝向、使用关系 | |
| `composition` 构图参考 | 位置、角度、大小和布局 | 可用其他商品图 |
| `style` 视觉风格 | 背景、光线和氛围 | 可用其他商品图 |

**数组顺序 = 使用顺序**。字母 A/B/C 按此顺序标注。

## 3. 处理资料冲突

- `productRelation=other_product` 或 `no_product` 的图，不得当作主体外观依据
- `aiStatus=yes` 的图，细节可能失真；关键结构以 `same_product` + `aiStatus=no` 的图为准
- 图与文字矛盾时，以标注的「忽略」范围为准；无法裁决处列入「待确认问题」
- 已确认方案冻结角色 / 采纳忽略 / 顺序，但不冻结图片自身的 `productRelation` / `aiStatus`

## 4. 组织方案与提示词

输出四部分（见 `10-io-contract.md`）：

1. **设计说明** — 构图、光影、视角为何这样选
2. **参考图使用安排** — A/B/C 各自用什么、忽略什么
3. **生图提示词** — 最终交给生图模型的文本
4. **待确认问题** — 事实不足、需用户拍板处

原则：

- 保留用户原始制图要求原文（`drawingRequest`）
- 保留参考图身份（`refImageId`），不丢 ID
- 不把商品资料写死进规则文件
