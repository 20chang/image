# 车灯主图样例输出（人工编写）

> **人工编写、尚未模型实测** — 设计预期样例，非模型实测结果。用于对照 `car-light-main.case.json` 的输入，说明 main 族应产出什么。
>
> **依据边界**：设计选择（构图、光影、视角）可以发挥；商品结构描述必须来自 `product.facts` 或参考图 `desc`。输入中没有的结构细节，一律删除或列入待确认。

## 1. 为何采用该构图与光影

- **白底、干净背景**：商品主图需在列表流中快速识别，背景干扰会削弱主体；与用户制图要求「白底主图」一致。
- **正面偏 45°**：能看到灯身正面散热鳍片与侧面厚度，同时不至于像纯侧面那样丢失识别特征；与 A 图（`ref-A`）的既有视角一致，降低结构走样风险。
- **柔光防过曝**：铝合金灯身反光强，硬光会造成死白高光、看不清鳍片纹理；柔光保证高光不过曝、暗部有细节。
- **完整轮廓**：灯身与已描述的接口/线束均在画框内，不出画、不裁切；买家能判断实际形态。
- **构图留白**：借鉴 C 图（`ref-C`）的留白节奏（主体偏右上、左下留白），但 **只取构图**，不带入其商品、文字与 Logo。

## 2. A / B / C 各自使用什么、忽略什么

| 图 | 角色 | 使用 | 忽略 | 依据（仅来自输入） |
|----|------|------|------|-------------------|
| A `ref-A` | 主体依据（primary） | 灯身外观：整体造型、散热鳍片排布、灯头比例、表面色泽 | 背景 | `facts`：铝合金灯身带散热鳍片；`desc`：同款整体图，正面偏 45°；`same_product` + `aiStatus=no` |
| B `ref-B` | 细节补充（detail） | 接口形状：H7 卡扣轮廓、线束接头形态 | — | `facts`：H7 灯座、含线束；`desc`：接口特写，可见 H7 卡扣与线束接头；`same_product` + `aiStatus=no` |
| C `ref-C` | 构图参考（composition） | 构图：留白比例、主体位置、视线引导 | 其中的商品、文字和 Logo | `desc`：大面积留白 + 左下角 Logo，商品居中偏右上；`other_product`，不得提供主体外观 |

**冲突处理**：C 为其他商品海报，其商品外观不得混入；B 仅补充接口，不覆盖 A 的整体外观主张。

## 3. 最终生图提示词

> 下列提示词中，**商品结构**仅来自 `facts` 与 A/B 的 `desc`；**构图/光影**为设计选择。

```
白底电商主图。LED 车灯 H7 55W，铝合金灯身带散热鳍片（依据：商品事实；外观以 ref-A 为准）。
画面主体为车灯整体（ref-A 保留商品整体外观），正面偏 45° 视角，完整轮廓入画不裁切，主体居中偏上、左下留白（构图借鉴 ref-C，忽略其中的商品、文字和 Logo）。
柔光棚拍，光线均匀不过曝，高光保留鳍片纹理，暗部有细节，商品边缘清晰。
接口区域仅按 ref-B 补充接口细节：H7 卡扣轮廓与线束接头形态，不扩大为其他结构主张。
背景纯白，无任何文字、Logo、水印、其他商品或装饰元素。
```

## 4. 事实不足，需用户确认

1. **防水等级**：`facts` 写「防水等级未标注」— 主图文案与提示词均不出现 IP 等级；若需宣称防水，请提供实测/标称依据。
2. **附件清单**：`facts` 提到「含驱动电源与线束」，但 A/B 的 `desc` 未描述电源盒 — 本次售卖是否含电源盒？若含，需补一张含附件图或确认以文字说明。
3. **灯罩 / 接头颜色与材质**：上文已从提示词删除。若主图必须呈现，请提供实拍描述或补一张能看清该部位的参考图。
